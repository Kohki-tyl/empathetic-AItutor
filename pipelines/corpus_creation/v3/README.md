# v3コーパス再構築

既存の500対話を教師ターン単位で監査し、修正可能なターンだけを置換してv3コーパスを作成する。原本の`500_empathetic_dialogues.jsonl`は変更しない。

## スコア

各教師ターンを20点満点で評価する。

| 項目 | 配点 | 満点の条件 |
| --- | ---: | --- |
| 数学的正確性 | 4 | 生徒・教師の数式、計算、結論を検算し、教師の内容が正確 |
| 生徒回答の評価 | 3 | 正しい部分、誤り、誤概念を正確に区別 |
| 認知的共感 | 3 | 理解状態と必要な支援量の推定に発話上の根拠がある |
| 感情認識・情緒的支援 | 2 | 感情推定と支援が文脈に合う |
| 足場かけ | 3 | 自力で達成可能な一歩で、不必要な直接解答がない |
| 対話制御 | 2 | 反復せず、一度に一内容、原則1〜2文 |
| 理解確認・完了判定 | 3 | 理由を確認し、完了判定が適切 |

各項目の0点は重大な不備、満点はその観点について修正せず教師信号にできる品質を表す。

## 分類

### keep

次をすべて満たすターンとする。

- 合計17〜20点
- `critical_failure=false`
- 誤答追認がない
- 教師の数学的内容が正しい
- 生徒回答の正誤判定が正しい
- 数学的正確性3点以上
- 生徒回答の評価2点以上
- 理解確認・完了判定2点以上

### repair

次のいずれかに該当し、現在の教師ターンだけの置換で対話を回復できる場合とする。

- 合計10〜16点
- 合計17点以上だが、keepのハード条件を満たさない
- 数学的誤り、誤答追認、根拠の弱い状態推定などのcritical failureがあるが、当該ターンだけで修正可能

修正後は同じ基準で再監査し、`keep`になった場合だけv3へ採用する。

### reject

次のいずれかに該当するターンとする。

- 合計0〜9点
- 問題、生徒発話、過去の対話が破綻している
- 過去の誤りへ依存し、現在ターンだけでは回復できない
- 直後の生徒発話と両立する修正ができない
- 生徒発話や問題自体を変更しなければ一貫性を回復できない

`reject`を一つでも含む対話はv3コーパスから除外する。

数学的誤り、誤答追認、根拠のない認知・感情推定、反復、不適切な直接解答、理解未確認の完了判定を個別に検査する。`repair`したターンは同じJudgeで再監査し、`keep`になった場合だけ採用する。

## 実行

最初に少数件で接続と出力を確認する。

```powershell
python pipelines/corpus_creation/v3/rebuild_v3_corpus.py --limit 3 --overwrite
```

確認後、全件を実行する。

```powershell
python pipelines/corpus_creation/v3/rebuild_v3_corpus.py --overwrite
```

途中停止後は`--overwrite`を付けずに再実行する。成功済みのターンはスキップされる。

全対象ターンの初回監査が終わった時点で、次の形式の分類割合を一度だけ表示する。割合の分母は監査に成功した教師ターン数である。

```text
=== ターン監査分類（完了後に一度だけ表示） ===
対象: 2351 / 監査成功: 2351 / 未完了: 0
keep: ...件 (...%)
repair: ...件 (...%)
reject: ...件 (...%)
keep + repair: ...件 (...%)
```

出力：

- `data/turn_audits.jsonl`：全教師ターンの監査
- `data/turn_repairs.jsonl`：修正内容と修正後の再監査
- `data/v3_rebuilt_corpus.jsonl`：全教師ターンが合格した対話
- `data/v3_rebuilt_corpus_manifest.json`：採否、判定数、除外理由

## SFTデータ

v3コーパス完成後に、完了対話を単一のSFT用JSONLへ変換する。

```powershell
python pipelines/sft/v3/prepare_v3_sft_dataset.py
```

既定では完了対話だけを採用する。train／validation分割は行わず、ABCI上のSFT設定で分割する。CoTには認知状態、感情状態、監査で得た具体的な数学的検証、次の一歩を含める。
