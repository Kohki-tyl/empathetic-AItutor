# v3コーパス採択基準

## 目的

v3コーパスでは、既存500対話を教師ターン単位で監査し、数学的誤り、誤答追認、不適切な状態推定、理解未確認の完了などをSFT教師信号から除外する。生徒発話と問題は変更せず、教師ターンだけで回復できる場合に限って修正する。

## ターン評価

各教師ターンを20点満点で評価する。

| 評価項目 | 配点 | 満点の条件 |
| --- | ---: | --- |
| 数学的正確性 | 4 | 生徒・教師の数式、計算、定義、結論を検算し、教師の内容が正確である |
| 生徒回答の評価 | 3 | 正しい部分、誤り、誤概念を区別し、誤答を追認していない |
| 認知的共感 | 3 | 理解済み事項、つまずき、必要な支援量の推定に発話上の根拠がある |
| 感情認識・情緒的支援 | 2 | 感情推定が文脈に合い、感情や努力を受容している |
| 足場かけ | 3 | 現在の理解で達成できる一歩を示し、不必要な直接解答を避けている |
| 対話制御 | 2 | 同じヒントを反復せず、一度に一内容、原則1〜2文である |
| 理解確認・完了判定 | 3 | 理由を確認し、偶然の正答や根拠のない回答で完了していない |

0点は重大な不備、各項目の満点はその観点について無修正で教師信号にできる品質を表す。

## Keep

次の条件をすべて満たす教師ターンをKeepとする。

1. 合計17〜20点である。
2. `critical_failure=false`である。
3. 誤答追認がない。
4. 教師の数学的内容が正しい。
5. 生徒回答の正誤判定が正しい。
6. 数学的正確性が3点以上である。
7. 生徒回答の評価が2点以上である。
8. 理解確認・完了判定が2点以上である。

合計点が高くても、数学的誤りや誤答追認を含むターンはKeepにしない。

## Repair

現在の教師ターンだけを置換して対話の一貫性を回復でき、次のいずれかに該当するターンをRepairとする。

1. 合計10〜16点である。
2. 合計17点以上だがKeepの必須条件を満たさない。
3. 数学的誤り、誤答追認、根拠の弱い状態推定、過剰な直接解答、反復、未確認の完了判定があるが、当該教師ターンだけで修正できる。

Repairでは、問題、生徒プロフィール、生徒発話、過去・未来の対話を変更しない。教師の`thought_process`、`student_emotion`、`roadmap_breakdown`、`next_step_plan`、`content`、完了判定だけを修正する。

修正後は同じ20点基準で再監査し、Keepになったターンだけを採択する。再度RepairまたはRejectになった修正は採用しない。

## Reject

次のいずれかに該当する教師ターンをRejectとする。

1. 合計0〜9点である。
2. 問題または生徒発話が破綻している。
3. 過去の数学的誤りに依存しており、現在ターンだけでは回復できない。
4. 直後の生徒発話と両立する教師ターンへ修正できない。
5. 問題、生徒発話、過去・未来の対話を変更しなければ一貫性を回復できない。

## 対話単位の採択

対話は次の条件をすべて満たす場合だけv3コーパスへ採択する。

1. 全教師ターンの初回監査が正常に完了している。
2. 初回Keepのターン、または修正後にKeepとなったターンだけで構成される。
3. Rejectターンを一つも含まない。
4. Repairの未修正、修正失敗、修正後Repair、修正後Rejectを含まない。
5. 生徒発話と教師発話の順序が維持されている。
6. 問題文、source ID、生徒プロフィール、生徒発話は原本から変更されていない。

`is_completed=false`の対話も、全教師ターンが合格していれば再構築コーパス自体には保持する。ただし、現在のSFTデータ変換では`is_completed=true`の対話だけを使用する。

## SFTデータとの関係

v3コーパスの採択と、SFT時の学習・検証分割は別処理とする。コーパス作成段階ではtrain／validationへ分割しない。SFT用には完了対話を単一JSONLへ変換し、分割率と乱数seedはABCI上のSFT設定で管理する。

## 実監査結果

| 項目 | 件数 |
| --- | ---: |
| 入力対話 | 500 |
| 監査対象教師ターン | 2,351 |
| 初回Keep | 2,056（87.5%） |
| 初回Repair | 253（10.8%） |
| 初回Reject | 42（1.8%） |
| Repair後Keep | 215 / 253（85.0%） |
| 最終採択対話 | 452 |
| 最終除外対話 | 48 |
| 採択対話中の完了対話 | 397 |

本基準はLLM Judgeによる自動監査の操作的定義である。SFT前には、Keep、Repair後Keep、Rejectから層化抽出して人手監査し、数学的誤りと誤答追認の見逃し率を確認する。
