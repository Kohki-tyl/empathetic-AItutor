# Test v2 分析レポート

## 結論

Baseとv2 SFTは各200件の対話生成を完了している。しかし、LLM Judgeによる評価は全件で接続エラーとなっており、近接転移正答率、共感指導スコア、数学的指導スコア、生徒らしさスコアは算出できない。また、生徒発話へのJSON露出とBase教師出力のCoT解析失敗が多数あるため、現在の結果だけからv2 SFTの有効性を結論づけることはできない。

生成ログ上では、v2 SFTはBaseより生徒の理解度・確信度を上昇させた一方、指導完了率は14.5ポイント低かった。ただし、これらは生徒シミュレータ自身が生成した内部状態であり、独立した学習成果の評価ではない。

## データの完全性

| 条件 | 対話ログ | 評価ログ | 正常なJSON | 生成エラー |
| --- | ---: | ---: | ---: | ---: |
| Base Swallow 8B | 200件 | 200件 | 200件 | 4件（2.0%） |
| v2 SFT Swallow 8B | 200件 | 200件 | 200件 | 1件（0.5%） |

生成エラーはいずれも、生徒の構造化応答に含まれる不正なバックスラッシュを原因とする`JSONDecodeError: Invalid \escape`であった。

| 平均Phase 1ターン数 | 7.000 | 7.705 | +0.705 |
| 平均理解度変化（0～4） | +0.325 | +0.500 | +0.175 |
| 理解度が上昇した対話 | 65件 | 99件 | +34件 |
| 平均確信度変化（0～1） | +0.045 | +0.076 | +0.031 |
| 確信度が上昇した対話 | 123件 | 142件 | +19件 |

同一200問による対応比較では、両条件で指導完了したものが59件、Baseだけが完了したものが57件、v2 SFTだけが完了したものが28件、両方未完了が56件だった。理解度変化は、v2 SFTがBaseを上回った問題が54件、同値が127件、Baseが上回った問題が19件だった。

| プロフィール | 件数 | Base完了率 | v2 SFT完了率 | Base理解度変化 | v2 SFT理解度変化 |
| --- | ---: | ---: | ---: | ---: | ---: |

v2 SFTでは全プロフィールで理解度変化がBase以上だったが、完了率は全プロフィールで低下した。特にV2-S01とV2-S04で完了率の低下が大きい。v2 SFTは短い足場かけを継続して内部状態を更新する一方、10ターン以内に`[指導完了]`へ到達しにくくなった可能性がある。

## 評価不能となっている項目

| Judge | Base成功件数 | v2 SFT成功件数 |
| --- | ---: | ---: |
| Phase 2数学正誤 | 0/200 | 0/200 |
| 共感指導評価 | 0/200 | 0/200 |
| 数学的指導評価 | 0/200 | 0/200 |
| 生徒らしさ評価 | 0/200 | 0/200 |

全レコードに`APIConnectionError: Connection error.`が保存されている。したがって、現時点では近接転移正答率や各指導スコアを0として扱ってはならず、欠測値として扱う必要がある。

さらに、評価スクリプトの`completed_ids()`はJudgeの成功・失敗を確認せず、`run_id`が存在する全レコードを完了済みと判定する。このため、接続を直して同じ出力先へ通常再実行しても全件がスキップされる。再評価時は既存ログを退避したうえで`--overwrite`を指定するか、エラー行だけを再試行できるよう判定処理を修正する必要がある。

## シミュレーションの妥当性に関する問題

### 1. 生徒発話へのJSON露出

| 条件 | 生徒ターン | JSON形式に見える発話 | 500文字超の発話 |
| --- | ---: | ---: | ---: |
| Base | 1,400 | 1,036（74.0%） | 1,033（73.8%） |
| v2 SFT | 1,541 | 1,092（70.9%） | 1,081（70.1%） |

生徒の`utterance`へ、`problem`、`state_before`、`latest_teacher_utterance`などを含むJSON全体が出力される例が多数ある。これは1～2文の自然な生徒発話という制約に反し、教師が通常の生徒には見えない内部状態を参照できる情報漏洩でもある。この状態では、生徒らしさと教師の認知的共感を公正に評価できない。

### 2. 状態更新の信頼性

Baseでは1,400生徒ターン中1,076件、v2 SFTでは1,541ターン中1,175件の`state_update_reason`が「構造化応答を解析できなかったため、直前の状態を維持しました」となっていた。割合はそれぞれ76.9%と76.2%である。この文言自体は生徒モデルの構造化出力内に生成されたものであるが、内部状態が大部分のターンで更新されていないことを示している。

したがって、平均理解度変化や確信度変化は参考値に留める。プロフィール更新方式の効果を測るには、状態更新の成功条件をプログラム側で検証し、失敗時の再生成を行う必要がある。

### 3. Base教師のCoT解析失敗

Base教師の1,400ターン中1,193件で、生徒へ渡された`content`内に`<analysis>`が残っていた。また、`<final>`開始タグを含む1,182件すべてで終了タグ`</final>`が欠落していた。`parse_teacher_response()`は終了タグがない場合に生のモデル出力全体を教師発話として扱うため、内部分析が生徒へ露出している。

一方、v2 SFTでは1,541教師ターンすべてで内部分析を別フィールドへ抽出でき、生徒向け発話への`<analysis>`露出は0件だった。平均教師発話長もBaseの364.7文字に対してv2 SFTは55.8文字であり、v2 SFTがCoTと最終発話の分離および簡潔な応答形式を学習したことは確認できる。ただし、Baseの比較条件が解析失敗によって不利になっているため、この差をそのままモデル能力差とは解釈できない。

### 4. 教師checkpointの識別不能

両条件のログに保存された`teacher_model`は、いずれも`tokyotech-llm/Llama-3.1-Swallow-8B-Instruct-v0.5`である。フォルダー名はBaseとv2 SFTに分かれているが、ログだけではv2 SFT checkpointが実際に提供されたことを検証できない。今後はcheckpointの絶対パスまたはHugging Face ID、revision、adapterパス、served model nameをmanifestへ記録する必要がある。

## 現段階で言えること

1. v2 SFTは、内部CoTと生徒向け最終発話を分離し、教師発話を大幅に短くする形式学習には成功している。
2. 生徒モデルの自己申告状態では、v2 SFTの方が理解度と確信度の上昇が大きい。
3. v2 SFTの指導完了率はBaseより低く、10ターン以内に指導を収束させる能力には課題がある。
4. Judge評価と生徒シミュレーションに重大な不備があるため、共感能力、数学的指導能力、近接転移、生徒らしさの優劣はまだ判断できない。

## 再評価前の優先修正

1. Judgeの接続設定を直し、エラー行を再評価できるようにする。
2. 生徒の`utterance`にJSONや内部状態が入った場合は再生成し、自然言語部分だけを教師へ渡す。
3. `state_update_reason`ではなく、状態オブジェクトの更新成否をプログラム側で判定する。
4. Baseの未閉鎖`<final>`を安全に解析するか、十分な生成長を確保して内部分析を生徒へ渡さない。
5. Baseとv2 SFTで実際にロードしたcheckpointをmanifestへ記録する。
6. 類似問題と模範解答を事前検証する。少なくとも確認した`math_train_1000`では、模範解答自身が「元の問題と同じ構造にならない」と述べており、近接転移問題としての品質に疑義がある。

以上を修正して同一200問を再評価した後に、Phase 2正答率、共感指導3指標、数学指導5指標、生徒らしさ4指標を条件間で対応比較する。
