# 教師モデル評価テスト設計

## 1. 目的

本テストは、数学教師モデルの次の性能を評価する。

- 対話生成成功率
- 対話全体における指導・共感品質
- 教師との対話後における類似問題正答率

評価対象は、生徒へ実際に提示された教師発話である。生徒LLM自体の能力、自然さ、プロフィール整合性、知識境界の遵守度は評価しない。

主要評価項目は対話生成成功率と対話全体の6軸得点とし、類似問題正答率は近接転移の副評価とする。

## 2. 評価ケース

評価ケースは100件とする。

- 翻訳済み問題をファイル順で見た末尾200問を母集団とする。
- 既存の構造検査で問題が見つかった18問を除外する。
- 残る182問から、固定seed `42` で100問を選定する。
- 各ケースに元問題、参照解答、類似問題、類似問題の参照解答を用意する。
- 学習コーパスとの `source_id` 重複がないことを機械検査する。

### 2.1 学習状況

学習状況は次の4区分とし、各25件を選定する。

| 学習状況 | 意味 | 件数 |
| --- | --- | ---: |
| `mastered` | 必要な考え方を習得済み | 25 |
| `frontier` | 学習の境界にあり、一部は自力で扱える | 25 |
| `one_step_beyond` | 既知事項から一段の接続が必要 | 25 |
| `far_beyond` | 現時点の学習範囲から離れており、着手から支援が必要 | 25 |

## 3. 生徒プロフィール

8種類の簡易プロフィールを使用する。生徒LLMへ渡すプロフィールは、学年、話し方、ケース別の初期状態から構成する。

```json
{
  "grade": "中学3年生",
  "speech_style": {
    "register": "タメ口",
    "confidence_expression": "慎重",
    "response_length": "標準"
  },
  "initial_state": {
    "learning_status": "frontier",
    "emotion": "confused",
    "emotion_reason": "方針がまだ安定していない",
    "initial_response": "どこから考えればいいのか迷ってる。"
  }
}
```

初期応答の事前生成前は、`initial_state` に `initial_response` を含めない。生成後は固定した初期応答を追加し、2回目以降の生徒発話生成と類似問題回答で使用する。

### 3.1 話し方

話し方は次のカテゴリで指定する。

- 口調：`タメ口` または `丁寧口調`
- 自信の表し方：`自信がある`、`慎重`、`控えめ`
- 発話量：`短い` または `標準`

タメ口と丁寧口調は4プロフィールずつ設定する。自信の表し方は言語表現上の傾向だけを意味し、数学能力、正答率、理解度、計算精度には結びつけない。

### 3.2 使用しないプロフィール要素

次の要素は設定しない。

- 計算精度などの数値パラメーター
- メタ認知能力
- 分野別習熟度
- 既習・未習内容の詳細一覧
- 固定された誤概念
- 誤答の強制

## 4. 初期感情

初期感情は次の6種類とする。

| 初期感情 | 件数 |
| --- | ---: |
| `frustrated` | 25 |
| `anxious` | 22 |
| `confused` | 18 |
| `engaged` | 18 |
| `curious` | 10 |
| `neutral` | 7 |

### 4.1 学習状況との関係

学習状況と初期感情には意図的な相関を持たせる。

| 学習状況 | 初期感情の内訳 |
| --- | --- |
| `mastered` | `engaged` 18件、`neutral` 7件 |
| `frontier` | `confused` 15件、`curious` 10件 |
| `one_step_beyond` | `anxious` 22件、`confused` 3件 |
| `far_beyond` | `frustrated` 25件 |

これは現実的な学習場面を構成するための複合シナリオである。学習状況と感情の独立した因果効果は推定せず、両者を独立要因として解釈しない。

## 5. 生徒LLM

生徒LLMは `gpt-5.4-2026-03-05` に固定する。

| 設定 | 値 |
| --- | --- |
| temperature | 0.6 |
| top-p | 0.95 |
| seed | 42を基準にケース別に決定 |
| 最大出力 | 4096トークン |
| 最大再試行 | 3回 |

APIエラー、空応答、形式破損だけを再試行する。次の理由では再生成・除外しない。

- 数学的な正誤
- プロフィールとのずれ
- 知識境界違反
- 初期状態とのずれ

## 6. 初期応答の固定

各問題・プロフィールについて、教師と対話する前の初期応答を1回だけ事前生成する。

生成後は次を保存する。

- ケースID
- 生徒モデル名
- seed
- 初期応答
- 初期応答のハッシュ
- 実行日時
- 再試行回数

同じ初期応答をすべての教師モデル条件へ渡す。条件間で同一ケースの初期応答ハッシュが異なる場合は、対応比較を停止する。

## 7. 教師との対話生成

教師モデルだけを条件間で変更し、次を固定する。

- 問題と参照解答
- 生徒プロフィール
- 学習状況と初期感情
- 初期応答
- 生徒LLM
- 生徒・教師プロンプト
- 最大ターン数
- seedと生成設定
- 再試行規則と停止規則

教師の最大ターン数は10とする。

教師プロンプトでは次を要求する。

- 生徒の内容と教師自身の説明を独立に検算する。
- 生徒の誤答を正しいと肯定しない。
- 感情を決めつけず、可視発話上の根拠から受け止める。
- 生徒が自力で越えられる一段階の足場を提示する。
- 同じ支援で進まない場合は支援方法を変更する。
- 理由、主要途中式、または同等の理解根拠を確認してから指導を完了する。

教師の内部推論は生徒へ提示せず、評価対象にも含めない。

## 8. 対話生成成功率

対話生成成功率は、予定した100ケースすべてを分母とする。

API・形式上の失敗がなく、教師による指導完了または最大ターンへ到達した場合を生成成功とする。数学的・教育的な品質は生成成功率へ含めず、6軸評価で別に測定する。

停止理由と完了フラグは運用記録および生成成功率の集計には使用するが、6軸評価を行うJudgeへは渡さない。

## 9. 対話全体の6軸評価

評価単位は対話全体とし、ターンごとの得点は付けない。各軸を0〜10点の整数、または評価機会が存在しない場合だけ `NA` として評価する。

### 9.1 指導評価

- 数学的正確性
- 誤り診断と回復
- 指導完了判定

### 9.2 共感評価

- 足場かけ
- 情緒的支援
- 感情把握

### 9.3 共通アンカー

| 得点 | 基準 |
| ---: | --- |
| 10 | 要件を一貫して満たし、明確な問題がない |
| 8 | おおむね満たすが、軽微な不足がある |
| 6 | 部分的に満たすが、教育上無視できない不足がある |
| 4 | 不足が大きく、指導効果を明確に弱める |
| 2 | ほとんど満たさず、指導を妨げる |
| 0 | 評価軸の要件をまったく満たさない |

奇数点は、隣接する偶数アンカーの中間に位置する場合だけ使用する。

## 10. Judgeの評価入力

Judgeへ渡すのは次の3項目だけとする。

- 問題
- 参照解答
- 生徒と教師の可視対話

次の情報はJudgeへ渡さない。

- 生徒プロフィール
- 学習状況と初期感情
- 教師の内部推論
- 停止理由
- 完了フラグ
- APIメタデータ
- 教師モデルの条件名

数学的検算には問題と参照解答を使用するが、教師の採点根拠には可視対話だけを使用する。指導完了も、発話外の完了フラグではなく可視対話の内容だけから判定する。

## 11. `NA` の扱い

`NA` は、教師の対応が不十分だった場合ではなく、対話中に評価機会が存在しなかった場合だけ使用する。

| 評価軸 | `NA` を使用できる条件 |
| --- | --- |
| 数学的正確性 | 原則として使用しない |
| 誤り診断と回復 | 生徒が終始正しく、不確実性や不完全な推論もない |
| 指導完了判定 | 原則として使用しない |
| 足場かけ | 生徒が初回から根拠付きで自力完答し、追加支援が不要 |
| 情緒的支援 | 感情・困難・負担の手がかりがなく、教師も感情的介入を行わない |
| 感情把握 | 感情または中立状態を判断できる手がかり自体がない |

必要な対応を教師が行わなかった場合は、`NA` ではなくルーブリックに従って得点を付ける。

平均算出時は `NA` を分子と分母から除外する。対話全体の得点は次の60点換算とする。

```text
適用可能な軸の平均 × 6
```

集計時には、軸別の有効件数、`NA` 件数、対話ごとの適用可能軸数を併記する。

## 12. 重大失敗

重大失敗があっても、関連軸の得点を機械的に0点へ変更しない。6軸はルーブリックに従って採点し、重大失敗は別に記録する。

対象例は次のとおりである。

- 生徒の数学的誤答を正答として確定した。
- 教師が重大な数学的誤りまたは誤概念を導入した。
- 生徒の正しい推論を誤りと断定し、誤った修正を強制した。
- 未解決の誤りを残したまま指導を完了した。
- 生徒の明確な困難感情を否定、非難、嘲笑または威圧した。
- 対話履歴と矛盾する支援により、指導が回復不能になった。

各失敗について、該当発話、失敗内容、影響、回復状況、関連軸を保存する。

## 13. 類似問題による副評価

教師との対話終了後、生徒LLMへ類似問題を提示する。

入力は次のとおりである。

- 同じ生徒プロフィール
- 元問題
- 可視対話全体
- 類似問題

生徒LLMは元問題の数値的な答えをコピーせず、可視対話で得た考え方が適用できる場合に類似問題へ利用する。教師へ追加支援を求めず、最終回答だけを返す。

転移評価用Judgeには次だけを渡す。

- 類似問題
- 類似問題の参照解答
- 生徒の最終回答

類似問題正答率は副評価であり、教師モデルの全体得点には統合しない。

## 14. 集計と条件間比較

### 14.1 主要評価

- 対話生成成功率
- 対話全体の全体得点

### 14.2 内訳

- 6軸の平均、中央値、有効件数、`NA` 件数
- 指導評価平均
- 共感評価平均
- 重大失敗率
- 指導完了率
- 最大ターン到達率
- 類似問題正答率

教師条件間では、同一ケースによる対応比較を行う。全体得点と軸別得点などの差について、対応ブートストラップ95%区間を算出する。

学習状況と初期感情は相関を持つ複合シナリオであるため、両者の独立効果は主張しない。

## 15. 人手評価

最初に全件をLLM Judgeで評価する。その後の工程として、学習状況、初期感情、得点帯、重大失敗などで層化抽出した対話を人手で二重評価する。

人手評価では次を確認する予定である。

- 軸別得点の一致
- `NA` 判定の一致
- 重大失敗判定の一致
- 重み付きκなどの評価者間一致指標

現時点では人手評価を実施していない。
