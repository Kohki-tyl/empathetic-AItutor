# v4コーパス設計とSFT有効性の検討

## 1. 目的

v4コーパスは、日本語数学チューターに次の二つを同時に学習させるためのKeep-only SFTコーパスである。

1. **認知的共感タスクの改善**：生徒の発話と途中式から、理解済み事項、つまずき、誤概念、感情および必要な支援量を推定する。
2. **認知的共感指導の改善**：推定結果を、誤答追認を避けた正誤フィードバック、一段階の足場かけ、支援方法の変更、理解確認へ変換する。

共感表現を増やすこと自体は目的としない。状態推定が教師発話へ反映され、その後の生徒の理解と独立した近接転移課題の成績へつながることを最終目標とする。

## 2. 過去のSFTから得られた設計要件

同一50問によるv3-build比較では、Baseからv3 SFTへの変化は次の通りだった。

| 指標 | Base | v3 SFT | 変化 |
| --- | ---: | ---: | ---: |
| 共感指導 | 9.560 / 30 | 9.520 / 30 | -0.040 |
| 数学的指導 | 13.100 / 50 | 10.240 / 50 | -2.860 |
| 直接解答 | 52回 | 28回 | -24回 |
| 誤答追認 | 102回 | 136回 | +34回 |
| 指導完了率 | 68.0% | 54.0% | -14.0ポイント |
| 近接転移正答率 | 12.0% | 6.0% | -6.0ポイント |
| 生徒モデルの理解度変化 | +0.500 | +0.900 | +0.400 |

この結果は、非直接解答という表面的な形式は学習できても、数学的検証、誤り診断、適切な足場かけ、理解確認が伴うとは限らないことを示す。また、シミュレータ内部の理解度上昇は近接転移と一致せず、教育効果の主要指標にできない。

したがってv4では、非直接解答だけを良質とみなさず、数学的正確性、誤りの診断と回復、状態推定と発話の対応、理解確認を全ターンで同時に要求する。

## 3. コーパスの単位と規模

| 項目 | 設定 |
| --- | --- |
| 最終採択数 | 100対話 |
| 最大生成候補 | 120対話 |
| 最大指導ターン | 1対話10教師ターン |
| 問題源 | `translated_1000_math.jsonl` |
| 分割 | コーパス作成時にはtrain/validationへ分割しない |
| 採択単位 | 教師ターンを監査し、全教師ターンが合格した対話だけを採択 |
| 未完了対話 | 全ターンがKeepなら採択可能 |

100対話から得られる教師例数は、平均教師ターン数に依存する。平均6ターンなら約600例、10ターンなら最大1,000例である。ただし、同一対話内のターンは強く相関するため、600個の独立問題を学習する場合と同等ではない。

## 4. 生徒シミュレータ

### 4.1 モデルとプロフィール

生徒役には`tokyotech-llm/Qwen3-Swallow-8B-SFT-v0.2`を使用する。教師役とモデルを分離し、教師SFTモデルが自分自身を生徒として模倣する構成を避ける。

プロフィールは次の8種類をほぼ同数割り当てる。感情別プロフィールは作らず、教育課程位置と分野別習熟度を安定した属性とする。

| ID | 類型 | 主な教育的課題 |
| --- | --- | --- |
| V4-S01 | 基礎不足型（中学1年） | 既習範囲の不足、手順への表面的依存 |
| V4-S02 | 誤概念確信型（中学2年） | 誤った考えへの固執、援助要請の遅れ |
| V4-S03 | 標準型（中学3年） | 方針選択の迷い、適切な支援量の調整 |
| V4-S04 | 高校発展型（高校2年・数学II/B主要範囲） | 複数分野を統合する際の条件確認と検算 |
| V4-S05 | 初期代数学習型（中学1年） | 数の計算規則と文字式操作の混同 |
| V4-S06 | 代数優位型（中学3年） | 図形条件を代数操作だけで処理する傾向 |
| V4-S07 | 図形優位型（中学3年） | 確率で標本単位や重複を見落とす傾向 |
| V4-S08 | 高校基礎型（高校1年・数学I/A） | 公式の適用条件の省略 |

各プロフィールはESS E2としてカリキュラム位置、分野別習得段階、進行シグナルを持ち、E3として問題ごとに安定した誤概念または部分手続きを割り当てる。`prior_knowledge`を開始時の使用可能知識の完全な一覧とし、各発話で`knowledge_used`と`response_stage`を構造化出力させる。詳細は`ESS_E2_E3_STUDENT_DESIGN.md`に示す。

### 4.2 初期感情

初期感情の候補は次の6種類とするが、均等なランダム割当は行わない。

- `neutral`
- `engaged`
- `curious`
- `confused`
- `frustrated`
- `anxious`

各問題の必要範囲と対応プロフィールの学習範囲との差、および問題難度から初期感情を事前決定する。`frustrated`は範囲外であるだけでは付与せず、教師との対話前に既習操作を2回試して同じ箇所で停止した`prior_attempt_history`を必須とする。`bored`、`eureka`、`relieved`、`proud`は対話中の結果としてのみ生じる。

### 4.3 感情サイクル

感情は教師の共感語の有無だけで更新せず、直前の支援内容と実際の理解度変化に基づいて更新する。

```text
engaged / curious ⇄ confused ⇄ frustrated → bored
confused → eureka → proud / relieved
anxious → relieved / engaged
```

同一状態の維持を許し、変化する場合は原則一段階に制限する。最初の生徒発話では教師介入がないため、割り当てられた初期感情を維持する。感情はラベル名を発話せず、語調、ためらい、確信度、発話長へ表す。

生徒出力は`state_after`、`response_stage`、`knowledge_used`、`state_update_reason`、`utterance`からなる。理解度は1ターン最大1段階、感情は定義済み遷移内に制限される。

再設計では、初回発話で感情ラベルだけを保持して発話が完全正答・断定調になる問題を防ぐため、6感情それぞれに発話上の表出条件を与える。教師介入前には理解度、獲得知識、未習範囲、誤概念を変更できず、確信度変化を0.1以内に制限する。

### 4.4 問題順序、知識境界と初回応答条件

問題選定LLMは使用せず、`math_train_0`以降をIDの数値部分の昇順で使用する。事前対応表に問題分野、必要カリキュラム段階、プロフィール、範囲関係、初期感情、E3誤概念を保存し、候補indexとの対応を決定的に再現する。

範囲関係の目標比率は`mastered` 40%、`frontier` 35%、`one_step_beyond` 20%、`far_beyond` 5%とする。各問題で実現可能な範囲関係のうち、累積件数が目標比率に最も遅れている関係を選び、その関係を満たすプロフィールの割当件数が均等になるよう決定する。問題順は変更しない。

MATHの`level`は学校段階を表さないため、教育課程段階は問題文・参照解答の数学用語から規則ベースで別途推定する。levelは同一範囲内の課題難度として感情と自力到達可能性の調整にだけ用いる。範囲関係が`one_step_beyond`または`far_beyond`の場合、初回応答を`scope_limited_help_seeking`へ強制する。

初回応答条件はE3誤概念から決定する。`frontier`では分野固有の誤概念による誤答または部分手続き、`mastered`では条件確認・検算が一箇所不足した回答、範囲外では援助要請とする。無関係なランダム計算ミスは生成しない。

## 5. 教師候補生成

教師候補は`gpt-5.6-terra`、reasoning effort `high`で生成する。再設計前pilotで参照解答と異なる生徒の結論を正答として追認した例があったため、候補生成でも数学的再検算を優先する。Repairは`medium`とする。問題選定用のAPI呼出しは行わない。

### 5.1 内部判断

内部判断は12個の独立フィールドへ分散させず、次の5ブロックへ整理する。

1. `mathematical_assessment`
   - `status`：correct / partially_correct / incorrect / unclear
   - `verification`：生徒回答と提示予定内容の独立検算
   - `correct_part`：正しい着眼点、式、計算
   - `error_part`：誤り、未確認部分、曖昧さ
2. `learner_state`
   - `cognitive_state`：理解済み事項、つまずき、誤概念、理解水準
   - `emotion`：10種類の学習感情
   - `evidence`：認知・感情判断の発話上の根拠
3. `support_decision`
   - `next_support`：今回扱う一つの支援
   - `change_reason`：支援方法を変更する理由。変更しない場合は「なし」
4. `is_completed`
   - 理由を含む正解と理解確認が成立した場合だけtrue
5. `teacher_utterance`
   - 生徒へ提示する最終発話

毎ターン問題全体のロードマップを再生成しない。これは内部出力の重複と長文化を減らし、検算、状態推定、支援選択の対応を明確にするためである。

### 5.2 判断と発話の順序

内部では、感情を受容する文を作る前に数学的検証を完了する。これにより、励ましのつもりで誤答を肯定することを防ぐ。

最終発話は原則3文とする。

1. 感情、努力、または正しい着眼点の具体的な受容
2. 正しい部分と修正すべき部分の数学的に正確な提示
3. 生徒が自力で越えられる一つの問いまたはヒント

不安・フラストレーションが強い場合、または一つの補足説明が必要な場合だけ4文目を許容する。文数を満たすための冗長化は禁止し、一度に新しく扱う内容は一つに限定する。

完了時は例外として新しい問いを出さず、`next_support`と`change_reason`を「なし」とし、確認済みの理由を要約して閉じる。最新回答が正しくても理由が不足する場合は未完了とし、一つの確認質問だけを出す。プログラムもこの整合性を検査する。

## 6. 生成モデルと実行方式

| 工程 | モデル | 実行方式 |
| --- | --- | --- |
| 生徒生成 | Qwen3-Swallow-8B-SFT-v0.2 | ABCI上のvLLM 0.25.1、revision固定、`qwen3` reasoning parser |
| 教師生成 | gpt-5.6-terra | Chat Completions API、reasoning `high` |
| 初回監査 | gpt-5.6-terra | Batch Chat Completions、reasoning `high` |
| Repair | gpt-5.6-terra | Batch Chat Completions、reasoning `medium` |
| 再監査 | gpt-5.6-terra | Batch Chat Completions、reasoning `high` |

教師生成は前ターンへ依存するため逐次実行する。初回監査はターン単位、Repairは対話単位、再監査は修正済み対話の全教師ターンをBatch処理する。設定値、seed、モデル名、reasoning effort、student revision、vLLM版、プロンプトのSHA-256、run fingerprint、Batch IDをmanifestへ保存する。

Qwen3-Swallowはモデルカード上thinkingのON/OFF切替をサポートしないため、`enable_thinking=False`は指定しない。vLLM起動時に`--reasoning-parser qwen3`を指定する。

### 6.1 Chat Completionsとreasoning

`gpt-5.6-terra`はChat Completionsを利用でき、Chat Completionsの`reasoning_effort`もサポートされる。現在の実装で使用するトップレベルの`reasoning_effort="medium"`または`"high"`は有効である。[GPT-5.6 Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra)／[Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)

Responses APIでは指定方法が`reasoning={"effort": "medium"}`となり、推論項目の保持、`reasoning.context`、previous responseによる継続、pro modeなどを利用できる。OpenAIは推論・ツール利用・マルチターンの新規処理にResponses APIを推奨しているが、Chat Completionsでreasoning自体が使えないという意味ではない。[Model guidance](https://developers.openai.com/api/docs/guides/latest-model)

v4では次の理由からChat Completionsを維持する。

- 教師の判断はStructured Outputsとして可視の5ブロックへ保存する
- 対話履歴はアプリケーション側でmessagesとして明示的に管理する
- 初回監査・文脈付きRepair・全対話再監査を`/v1/chat/completions`のBatchへ統一できる
- Responses API固有の推論項目やツール呼び出しを必要としない

将来、隠れた推論状態を複数ターンで継承する、pro modeを使う、Responses固有のツールを使う場合はResponses APIへ移行する。

## 7. 監査、Repair、採択

### 7.1 60点監査

全教師ターンを次の6項目で各10点評価する。

| 項目 | 主な判定対象 |
| --- | --- |
| 数学的正確性 | 数式、計算、定義、結論の正しさ |
| 誤りの診断と回復 | 正答・部分正解・誤答・誤概念の区別と修正 |
| 認知的共感 | つまずきと必要な支援量の根拠付き推定 |
| 感情認識・情緒的支援 | 感情の根拠付き推定と心理的安全性 |
| 適応的足場かけ | 一段階の支援、停滞時の方法変更、直接解答の抑制 |
| 理解確認・完了判定 | 理由を確認したうえでの完了判定 |

### 7.2 Keep

Keepには次のすべてを要求する。

- 6項目がすべて8点以上
- Critical failureがない
- 誤答追認がない
- 教師自身の数学的誤りがない
- 内部の数学的検証と最終発話が矛盾しない
- 認知・感情分析が受容対象、正誤説明、問い、ヒント、説明量または支援変更へ反映される
- 生徒のプロフィール、役割、知識、状態更新、初期感情が妥当である

合計点による弱点の相殺は認めない。1項目でも8点未満ならKeepにしない。

### 7.3 RepairとReject

現在の教師ターンだけを置換し、問題、生徒発話、他の教師ターンを変更せず、直前と直後を含む対話全体に整合させられる場合だけRepairとする。生徒のプロフィール逸脱、役割逸脱、不自然な状態更新、初期感情不一致など、固定された生徒側文脈が原因ならRejectとする。

同じ対話に複数のRepair対象がある場合、それぞれを独立に書き換えず、対話全体と全監査結果を一度に入力してまとめて修正する。修正後はRepairターンだけでなく、修正済み対話の全教師ターンを同じJudgeで再監査する。全ターンがKeepになった場合だけ採択し、一つでも非Keep、監査欠落、修正エラーがあれば対話全体をRejectする。Repairの反復は行わない。

## 8. SFT形式

採択対話は、教師用system prompt、生徒発話を`user`、教師発話を`assistant`とするmessages形式へ変換する。問題と最初の生徒発話は一つの`user`へ結合し、roleを`system → user → assistant`以降交互にする。教師assistant出力は次の形式を持つ。

```text
<analysis>
【数学的評価】検算、回答分類、正しい部分、修正点
【生徒状態】認知状態、感情、発話上の根拠
【支援判断】一つの支援、支援変更理由
</analysis>
<final>
受容 → 数学的正誤 → 一つの問い・ヒント
</final>
```

これは自由記述の長いCoTではなく、検証可能な短い判断記録である。各analysisブロックは原則1文とし、問題や対話の再述を含めない。SFTでは状態推定だけでなく、推定から支援を選び、最終発話へ反映する対応関係を学習対象とする。

lossはsystemとuserをマスクしたassistant-only lossとする。各モデルのchat template適用後にtoken長を計測する。v4のfinalizeは分割を自動実行しないため、上限超過対話はSFT前処理側で教師ターン境界に分割する。assistant targetの途中での切り詰めは行わない。主評価ではBaseとSFTの両方へv4と同一の教師system promptを使い、旧test-v2 promptは頑健性評価に分ける。実行仕様は[SFT_FORMAT.md](./SFT_FORMAT.md)に示す。

## 9. v4で改善が期待できる点

| 過去の問題 | v4の対策 | 改善見込み |
| --- | --- | --- |
| 直接解答の抑制だけが学習された | 正確性、診断、足場かけ、理解確認を全項目8点以上で同時要求 | 高い |
| 誤答追認が増えた | 内部検算を最初に実施し、誤答追認をCritical failure化 | 中〜高 |
| 認知状態の分析が発話へ反映されない | `learner_state → support_decision → teacher_utterance`を明示しJudgeでも確認 | 中程度 |
| 同じ問いを反復する | `change_reason`で支援変更理由を明示 | 中程度 |
| 理解未確認で完了する | 理由を含む正答時だけ`is_completed=true` | 中程度 |
| 生徒が盲目的に同意する | 教師と生徒を別モデル化し、状態遷移と知識制約を追加 | 中程度 |
| 感情困難例が不足する | 範囲関係と難度から初期感情を事前決定し、分布を採択前後で監査 | 中程度 |
| 生徒が未習公式を最初から使用する | 問題・参照解答と既習／未習範囲を事前照合し、適合問題だけを割当 | 中〜高 |
| 作為的なランダム誤答へ偏る | E3誤概念のtrigger・faulty procedure・observable signatureを固定 | 中〜高 |
| 完了後も追加質問する | 完了時の支援なし・疑問形なしを生成時に機械検査 | 高い |
| 内部判断が冗長で不整合になる | 12項目から5ブロックへ統合し、ロードマップ反復を削除 | 中〜高 |

特に、教師発話の形式、直接解答の抑制、明示的な検算、状態推定を支援へ接続する出力様式は、SFTで比較的学習されやすいと考えられる。

## 10. 成果が保証できない理由

### 10.1 100対話は行動形成の最小規模に近い

約600〜1,000教師ターンが得られても、問題、感情、プロフィール、誤概念、指導段階の組合せを十分に覆えるとは限らない。8BモデルのLoRA SFTでは、3文形式や非直接解答のような表層パターンは学習できても、未知問題の数学的検証能力そのものが大幅に向上する保証はない。

したがって100対話は、設計仮説を検証する最初の本実験規模としては利用できるが、最終コーパス規模として十分とは断定できない。

### 10.2 120候補では100対話へ到達しない可能性がある

全教師ターンKeepを要求するため、ターン単位合格率が高くても対話単位採択率は低下する。平均6ターンの場合、120候補から100対話を得るには、初回または全対話再監査後の各教師ターンの実質合格率が概算で約97%以上必要である。平均10ターンなら約98%以上が必要になる。

Repairによって採択率は上げられるが、20件の予備候補だけでは不足する可能性が高い。100件未達時に候補を追加生成できる運用が必要である。

### 10.3 生成・修正・監査が同一モデル系列である

教師生成、Repair、Judgeをすべて`gpt-5.6-terra`で行うため、同じ数学的誤り、文体選好、状態推定の癖を共有する可能性がある。プロンプトとAPI呼び出しを分離しても、評価者独立性は完全には得られない。

少なくとも、初回Keep、Repair後Keep、Reject、複雑な数学問題、各初期感情から層化した人手監査が必要である。可能な問題には決定的な数式・数値検算を追加することが望ましい。

### 10.4 生徒条件の同期と外的妥当性

v4コーパス作成とtest-v4では、生徒モデル、プロフィール、初期感情、知識境界、感情サイクル、構造化状態、`response_stage`、`knowledge_used`の検査を同期する。これにより、教師条件以外の生徒反応分布が異なる交絡を抑える。

一方、同一の生徒LLMとプロンプトへの最適化だけでは、実際の生徒や別の生徒モデルへの一般化を示せない。主実験では同期条件を固定し、別モデル・別プロンプトによる頑健性評価を追加実験として分ける必要がある。

### 10.5 問題難度とプロフィール既習範囲の対応に残る不確実性

再設計前は問題をプロフィールと独立に割り当てていたため、V2-S01へ高校範囲や競技数学相当の問題が割り当てられ、10ターン以内の自力到達が現実的でない場合があった。

#### 過去実験による確認

test-v2はHendrycks MATHベンチマーク由来であり、中学生V2-S01の既習範囲を越える高校・競技数学相当の問題を含む。182問のv2-buildについて、V2-S01へ割り当てられた問題をMATHの難度1〜2と難度3〜5に分けて再集計した。

| 教師 | 問題難度 | 件数 | 10ターン内完了率 | 平均Phase 1ターン | 近接転移正答率 |
| --- | --- | ---: | ---: | ---: | ---: |
| Base | 1〜2 | 11 | 72.7% | 5.364 | 18.2% |
| Base | 3〜5 | 37 | 67.6% | 6.243 | 8.1% |
| v2 SFT | 1〜2 | 11 | 63.6% | 6.091 | 18.2% |
| v2 SFT | 3〜5 | 37 | 24.3% | 9.243 | 8.1% |

Baseでは難度3〜5で完了率が5.1ポイント低下し、平均ターンが0.879増えた。v2 SFTでは完了率が39.3ポイント低下し、平均ターンが3.152増えた。またv2 SFTのプロフィール別集計でも、V2-S01は完了率33.3%、平均8.521ターンであり、V2-S02〜S04の完了率52.3〜60.9%、平均6.457〜7.205ターンより到達が遅かった。

旧v1-buildでもBaseでは難度1〜2の完了率66.7%に対し難度3〜5は47.1%だったが、v2 SFTでは33.3%対35.3%で差が再現しなかった。さらに、MATHのlevelは競技問題としての難度であり、学校段階の学習範囲ラベルではない。プロフィールごとに異なる問題が割り当てられているため、この集計だけでは問題範囲の因果効果を分離できない。

したがって、**V2-S01への高難度問題割当がターン内到達を難しくする仮説は、主要なv2-build、とくにSFT教師で強く支持されるが、全条件で一貫して確認されたとはいえない**。問題範囲の不一致は有力な要因である一方、SFT後の足場かけや完了判定との相互作用も含む。

再設計後も問題順序は固定するため、低学年プロフィールへ範囲外問題が割り当てられること自体はある。ただし、それを選定で隠すのではなく、初回を条件整理と具体的な援助要請へ制限し、教師が知識境界に応じて足場を構築できるかを学習対象にする。`knowledge_used`はプログラム検査とJudge監査を行うがモデルの自己申告でもあるため、採択後に範囲外問題を層化抽出して人手確認する必要がある。

### 10.6 厳格採択による分布の偏り

厳しい採択基準は低品質信号を除ける一方、Frustrated、Bored、強固な誤概念、長期停滞など難しい条件ほどRejectされやすい。最終100件の件数だけを満たすと、容易なEngaged対話へ偏る可能性がある。

プロフィール、初期感情、対話中感情、完了・未完了、Repair有無、誤概念が複数ターン持続した例の分布を採択後に確認する必要がある。不足条件はラベルを書き換えず、該当候補を追加生成する。

### 10.7 コーパス品質とSFT設定は別問題である

適切なコーパスでも、学習率、epoch、LoRA rank、対象module、最大系列長、packing、分析部と最終発話のloss設計によって結果は変わる。特に100対話へ過剰適合すると、3文構造は再現できても数学的能力や近接転移が低下し得る。

## 11. 総合判断

### 11.1 得られそうな成果

次の成果は比較的期待できる。

- 直接解答の減少または低水準の維持
- 出力前に数学的検証を明示する形式の定着
- 誤答の正しい部分と修正点を分離する発話の増加
- 受容、正誤、次の一歩からなる教師発話構造の定着
- 認知・感情状態と支援選択の対応の改善
- 未確認の完了判定と明白な誤答追認の減少

### 11.2 現時点で不確実な成果

次はコーパス設計だけでは保証できない。

- 未知の数学問題に対する数学的正確性の大幅な向上
- 生徒感情の客観的な認識精度
- 指導完了率の向上
- 近接転移正答率の向上
- 実際の中学生に対する学習効果

### 11.3 結論

v4は、v2/v3 SFTで観測された主要な失敗原因へ、これまでより直接的かつ整合的に対処している。そのため、**教師の応答形式、誤答追認、診断、状態に応じた支援選択については改善する可能性がある**。一方、**100対話のKeep-only SFTだけで近接転移や真の教育効果まで改善すると予測する根拠はまだ弱い**。

したがってv4 SFTは「成果が得られる完成版」ではなく、次の仮説を検証する実験として位置づけるのが妥当である。

> 全項目8点以上のターンだけで構成し、数学的検証、学習者状態、支援判断を短い構造化判断として学習させると、非直接解答だけでなく、誤答追認、認知的共感、誤り診断、理解確認も同時に改善するか。

この仮説には十分な合理性があるが、採否はSFT後の外部評価で判断する必要がある。

## 12. 共感タスクの改善可能性

### 12.1 現時点の実証結果

この研究で得られている結果だけを見ると、SFTによる共感精度向上はまだ確認されていない。

- test-v2の182問では、共感指導がBaseの10.220/30に対してv2 SFTは9.407/30だった。
- 同一50問のv3-buildでは、Base 9.560/30に対してv3 SFTは9.520/30で、差は-0.040だった。
- v3-buildの95%対応ブートストラップ区間は-1.180〜+1.080であり、改善を支持しなかった。
- v3 SFTでは、感情認識が+0.120だった一方、認知的共感は-0.160、情緒的支援は同点だった。

したがって、「共感データでSFTすれば共感精度が上がる」という一般的な仮定は、この研究の結果では支持されていない。

### 12.2 v4で改善可能性が高まる理由

v4は従来より共感タスクへ直接的な教師信号を持つ。

| 共感下位タスク | v4の教師信号 | 改善見込み |
| --- | --- | --- |
| 感情認識 | `learner_state.emotion`と発話根拠、感情サイクル、困難感情の層化生成 | 低〜中 |
| 認知的共感 | `cognitive_state`で理解済み事項・つまずき・誤概念を推定し、`support_decision`へ接続 | 中 |
| 情緒的支援 | 受容→正誤→一段階の支援という最終発話を全Keepターンで要求 | 中〜高 |

認知的共感と情緒的支援は、望ましい最終発話パターンを反復学習できるため改善可能性がある。特に、状態推定と支援判断が別々の自由記述ではなく、`learner_state → support_decision → teacher_utterance`として対応づけられた点はv2/v3より良い。

一方、感情認識精度の改善はより不確実である。感情ラベルと根拠は実在生徒のアノテーションではなくLLMシミュレーションとLLM監査から作られるため、誤ったラベルでも生成モデルとJudgeが同じ傾向を共有するとKeepになる可能性がある。また、共感評価は対話中の教師最終発話を主に観察するため、正確な感情認識ではなく共感的な言い回しを高く評価する可能性がある。

### 12.3 「共感らしい発話」と「共感タスク精度」の分離

v4 SFT後に次の変化だけが起きても、共感タスク精度が向上したとは判定しない。

- 受容表現や励ましが増えた
- 3文構成を守るようになった
- 感情ラベルを毎ターン出力するようになった
- 共感指導合計だけが微増した

共感タスク精度の向上には、少なくとも次を確認する。

1. **感情認識**：教師が予測した感情と、そのターン直前の生徒シミュレータ状態または人手ラベルの一致
2. **認知状態推定**：理解済み事項、誤概念、つまずきが生徒の式・発話と一致
3. **推定から指導への変換**：推定した状態に応じて、受容対象、説明量、問い、ヒントまたは支援方法が変化
4. **結果妥当性**：次の生徒ターンで期待した理解更新が観測され、近接転移を悪化させない

### 12.4 必要な追加評価

現行の共感Judge評価に加えて、教師の`<analysis>`から次を抽出して評価する。

- `learner_state.emotion`と生徒の`state_before.emotion`の一致率
- 感情別の再現率。特にConfused、Frustrated、Bored、Anxiousを個別に報告
- `cognitive_state`が生徒のactive misconceptionと整合する割合
- `support_decision`が推定した状態へ対応している割合
- 同じ生徒発話に対し、プロフィールまたは感情だけを変えたとき支援が適切に変化するか

LLMシミュレータの状態は完全な正解ラベルではないため、困難感情、誤概念、Repair後Keepから層化抽出したサンプルを人手でも評価する。感情認識、認知的共感、情緒的支援は合計点だけでなく、それぞれの問題単位対応差と95%区間を報告する。

### 12.5 共感タスクに関する判断

v4によって、**認知的共感と情緒的支援が改善する可能性は従来コーパスより高い**。ただし、**感情認識精度の向上は、合成ラベルと同一モデルJudgeへの依存から現時点では弱い予測に留まる**。

よって、v4 SFTは共感改善を期待できる設計ではあるが、まだ改善を確認した設計ではない。成功判定には、共感合計の上昇だけでなく、感情ラベル一致、認知状態推定、支援への反映、近接転移非劣化を同時に要求する。

## 13. SFT後の評価と判断基準

Baseとv4 SFTを、同一問題、同一seed、同一プロフィール、同一初期感情で対応比較する。内部理解度変化は副次指標とし、主要指標を次のように置く。

1. 感情認識、認知的共感、情緒的支援
2. 数学的正確性、誤りの診断と回復、適応的足場かけ、理解確認、認知負荷
3. 誤答追認回数
4. 不必要な直接解答回数
5. 指導完了判定と実際の理解の一致
6. 元問題および近接転移問題の正答率
7. 生徒の知識逸脱、教師役逸脱、盲目的同意、不自然な状態更新

「理解度変化だけが上昇した」「直接解答だけが減った」「共感合計が微増した」場合は成功としない。少なくとも次を同時に満たす必要がある。

- 共感指導と数学的指導がともにBaseを上回る
- 認知的共感と誤りの診断・回復が低下しない
- 誤答追認が減少する
- 直接解答の減少が数学的正確性の低下によって生じていない
- 近接転移正答率が低下しない
- 生徒シミュレータの不自然な追従が増えない

平均差だけでなく、問題単位の対応差と95%ブートストラップ区間を報告する。SFTによる目的行動の変化を確認するには、100問を最低線とし、可能であれば200問まで評価する。さらに、初回Keep、Repair後Keep、感情困難例、数学的難問を含む層化サンプルを人手評価し、LLM Judgeとの一致を確認する。
