# SFT v3 / v4 概要資料

更新日: 2026-07-26

## 1. エグゼクティブサマリー

SFT v3とv4は、どちらも`tokyotech-llm/Llama-3.1-Swallow-8B-Instruct-v0.5`を、数学を教える共感的AI教師へ適応する試みである。ただし、改善の中心は異なる。

- **v3**は、既存500対話を教師ターン単位で監査・修正し、完了した397対話を4-bit QLoRAで学習する。データ量を確保しつつ、明確な低品質ターンを除去する設計である。
- **v4**は、学習範囲、生徒プロフィール、初期感情を計画的に割り当てた120候補から104対話だけを採択し、BF16 LoRAで慎重に学習する。データの構成、数学能力の保持、学習・評価の再現性を重視する設計である。
- v4の実評価では、**対話継続、情緒的支援、理解確認、生徒らしさ**には改善が見られた。一方、**数学的正確性、誤り診断、適応的な足場かけ、最終正答率**は改善せず、総合性能がv3を上回ったとは結論づけられない。

要するに、v3からv4への変更は「より多くの良質例を学習する」から「少量でも意図を明確にした高品質例を、基盤能力を壊しにくい方法で学習する」への転換である。ただし、v4の狙いと実性能にはまだ隔たりがある。

## 2. 全体像

```text
v3
既存500対話
  → 2,351教師ターンを監査
  → Keep / Repair / Reject
  → 452対話を採択
  → 完了397対話をSFT
  → 4-bit QLoRA

v4
問題・学習範囲・プロフィール・感情を計画配置
  → 120対話を生成
  → 対話全体を60点基準で監査・Repair
  → 105対話Keep
  → 構造ゲート通過104対話をSFT
  → BF16 LoRA + analysis/final重み付きloss
```

## 3. v3の概要

### 3.1 目的

既存コーパスに含まれる数学的誤り、誤答追認、不適切な状態推定、過剰な直接解答、理解未確認の完了を教師信号から除外する。問題、生徒プロフィール、生徒発話は維持し、教師ターンだけで回復可能な場合にRepairする。

### 3.2 コーパス作成

各教師ターンを次の7観点、20点満点で評価する。

1. 数学的正確性
2. 生徒回答の評価
3. 認知的共感
4. 感情認識・情緒的支援
5. 足場かけ
6. 対話制御
7. 理解確認・完了判定

採択は厳格なゲート方式である。合計17点以上でも、数学的誤り、誤答追認、正誤判定ミスなどがあればKeepにしない。Repair後もKeepにならないターン、またはRejectターンを1つでも含む対話は除外する。

| 項目 | 結果 |
| --- | ---: |
| 入力対話 | 500 |
| 監査対象教師ターン | 2,351 |
| 初回Keep | 2,056（87.5%） |
| 初回Repair | 253（10.8%） |
| 初回Reject | 42（1.8%） |
| Repair後Keep | 215 / 253（85.0%） |
| 最終採択対話 | 452 |
| SFT対象の完了対話 | 397 |
| SFT対象教師ターン | 1,626 |

### 3.3 教師出力形式

教師出力は`<analysis>`と`<final>`で構成される。v3の内部分析は4区分である。

```text
<analysis>
【認知状態】...
【感情状態】...
【数学的検証】...
【次の一歩】...
</analysis>
<final>
生徒へ提示する発話
</final>
```

完了対話の最終教師発話には`[指導完了]`を付与する。分析と最終発話は通常のassistant教師信号として同じ重みで学習される。

### 3.4 学習設定

| 項目 | v3 |
| --- | --- |
| 基盤モデル | Llama-3.1-Swallow-8B-Instruct-v0.5 |
| 学習データ | 397対話 |
| train / validation | 7 : 1（`val_size=0.125`） |
| 方式 | 4-bit QLoRA |
| LoRA | rank 16、alpha 16、dropout 0.05 |
| 対象層 | all linear |
| epoch | 3 |
| 学習率 | `1.5e-4` |
| 実効バッチ | 16 |
| 最大系列長 | 2,048 tokens |
| loss | assistant出力を一律に学習 |

### 3.5 特徴と課題

強みは、397対話という比較的大きな教師信号と、教師ターン単位の明示的な品質管理である。一方、最大2,048 tokens、4-bit量子化、高めの学習率、all-linear LoRAにより、長い対話の欠落や基盤モデルの数学能力への干渉が起こり得る。また、分析文が最終発話より長いため、内部CoTがlossを支配しやすい。

## 4. v4の概要

### 4.1 目的

v3で残った課題に対し、次を重点化する。

- 数学的正確性と誤答追認防止
- 生徒の既習範囲に応じた支援
- 認知状態と感情状態の根拠ある推定
- 同じヒントの反復を避けた適応的足場かけ
- 生徒自身の説明や検算に基づく完了判定
- 学習条件、データ、モデルrevision、出力の再現性

### 4.2 コーパス設計

v4では、問題を生徒の既習範囲との関係で4つに分け、8種類の生徒プロフィールと6種類の初期感情を割り当てる。

| 学習範囲 | SFT利用可能件数 |
| --- | ---: |
| mastered | 27 |
| frontier | 22 |
| one_step_beyond | 29 |
| far_beyond | 27 |

120候補を対話全体で監査し、6軸60点で品質を評価する。最終的に105対話がKeepとなり、制御文字を含む1対話を構造ゲートで保留して104対話・711教師ターンをSFTへ使用した。

| 項目 | 結果 |
| --- | ---: |
| 生成候補 | 120 |
| 初回Keep | 81 |
| Repair後Keep | 24 |
| 統合Keep | 105（87.5%） |
| SFT利用可能 | 104 |
| 教師ターン | 711 |
| 修正済み教師ターン | 55 |
| 品質平均 | 55.62 / 60 |

### 4.3 教師出力形式

外側の`<analysis>`・`<final>`はv3と共通だが、内部分析を3区分へ再整理した。

```text
<analysis>
【数学的評価】...
【生徒状態】...
【支援判断】...
</analysis>
<final>
生徒へ提示する発話
</final>
```

数学的検証を先に行い、その結果を踏まえて生徒状態と支援を判断する構造である。v3.1は、v3のデータと最終発話を変えず、この出力区分とsystem promptだけをv4形式へ合わせた統制条件である。

### 4.4 学習設定

| 項目 | v4 |
| --- | --- |
| 基盤モデル | Llama-3.1-Swallow-8B-Instruct-v0.5、revision固定 |
| 学習データ | 104対話、711教師ターン |
| train / validation | 94 / 10、seed 42固定 |
| 方式 | BF16 LoRA、単一H200 |
| LoRA | rank 16、alpha 32、dropout 0.05 |
| 対象層 | q/k/v/o projectionのみ |
| epoch | 4 |
| 学習率 | `5e-5` |
| 実効バッチ | 4 |
| 最大系列長 | 8,192 tokens、暗黙の切り詰めなし |
| loss | `<analysis>` 0.25、`<final>` 1.0 |

CoT 211,208 tokens、最終発話68,462 tokensに対し、重み付け後の教師信号は概算43.5%対56.5%となる。これにより、内部推論を残しながら、生徒に見せる最終発話を主目的にする。

### 4.5 学習実績

- 学習94件、検証10件、1 epoch 24 step、合計96 stepを完走
- 最長系列は学習6,683 tokens、検証5,835 tokensで、8,192上限内
- validation lossはepoch 1の1.0522からepoch 4の0.8990へ低下
- 最良checkpointはstep 96（epoch 4）
- 学習時間は約226秒
- データSHA-256、モデルrevision、split、環境、checkpointをmanifestへ保存

## 5. v3とv4の主要差分

| 観点 | v3 | v4 | 変更意図 |
| --- | --- | --- | --- |
| データの出発点 | 既存500対話 | 設計して生成した120候補 | 学習範囲・人物・感情の被覆を制御 |
| SFT対話数 | 397 | 104 | 量より構成と品質を優先 |
| 品質単位 | 教師ターン中心 | 対話全体＋構造ゲート | 履歴整合性と完了判定を重視 |
| 内部分析 | 4区分 | 3区分 | 数学評価→状態→支援の因果を明確化 |
| 量子化 | 4-bit | なし（BF16） | 数学能力低下の交絡を減らす |
| LoRA対象 | all linear | attention q/k/v/oのみ | 知識表現への広い介入を抑える |
| 学習率 | `1.5e-4` | `5e-5` | 小規模データでの過大更新を抑える |
| 最大系列長 | 2,048 | 8,192 | 対話履歴と判断記録を保持 |
| 実効バッチ | 16 | 4 | 少量データでも更新stepを確保 |
| loss | 一律 | analysis 0.25 / final 1.0 | 最終教師発話を重視 |
| checkpoint選択 | 15 stepごとに評価 | epochごと、最小validation loss | 過学習を監視 |
| 再現性 | LLaMA-Factory設定中心 | hash・revision・split・環境をmanifest化 | 実験追跡を強化 |

## 6. 評価結果

### 6.1 共通評価の考え方

test-v5では、問題60問、プロフィール、初期感情、推論prompt、sampling、seed、Judgeを固定し、生徒を`gpt-5.4-2026-03-05`に統一して教師adapterを比較する。v3とv4は学習時promptが異なるため、この比較は「同一の本番promptで使用したadapter性能」であり、コーパス内容だけの純粋な因果比較ではない。

### 6.2 v3 SFT

| 指標 | 結果 |
| --- | ---: |
| 生成品質通過 | 43 / 60（71.7%） |
| 品質通過分の指導品質 | 33.14 / 60 |
| 品質通過分の生徒らしさ | 6.81 / 10 |
| 品質通過分のPhase 2正答 | 23 / 43（53.5%） |
| Phase 1未完了 | 16 / 60 |
| 対話欠損 | 1 / 60 |

### 6.3 v4 SFT

初回60件では53件（88.3%）が生成品質を通過し、そのうち49件が完全Judgeされた。

| 指標 | v4 | 同一49問のBase | 差 |
| --- | ---: | ---: | ---: |
| Phase 2正答 | 18 / 49（36.7%） | 18 / 49（36.7%） | 0 |
| 指導品質 | 17.67 / 60 | 18.69 / 60 | -1.02 |
| Critical failure | 39 / 49 | 39 / 49 | 0 |
| 生徒らしさ | 7.80 / 10 | 7.27 / 10 | +0.53 |
| Phase 1ターン数 | 6.59 | 1.06 | +5.53 |

6軸では、情緒的支援が+0.80、理解確認・完了判定が+1.76改善した。一方、数学的正確性は-1.22、誤りの診断と回復は-0.59、認知的共感は-0.69、適応的足場かけは-1.06だった。

### 6.4 解釈

- v4はv3より生成品質通過率が高いが、評価済み集合が一致しないため、平均スコアや正答率の単純な横比較はできない。
- v4はBaseに対して、対話を継続し、情緒支援と理解確認を増やすという狙いどおりの行動変化を示した。
- ただし、長い対話の中で教師自身の誤計算、正しい生徒回答の誤訂正、同じ問いの反復が増えた。数学的正確性と足場かけの低下が総合改善を相殺している。
- v4の効果はmasteredに偏り、frontierとone_step_beyondでは完全評価例がすべてCritical failureだった。境界領域の診断と一段階の支援が最大の課題である。

## 7. 現時点の結論と次の改善

v4は、データ設計、学習の安全性、監査可能性、再現性の面でv3より洗練されている。特に、BF16 LoRA、限定した適用層、低学習率、長系列、重み付きloss、固定splitとmanifestは、実験基盤として明確な前進である。

一方、モデル性能としては、情緒的支援と理解確認の改善は確認できるものの、数学教師として最重要の正確性と誤り診断が不安定である。したがって、現段階のv4は**設計上の改善版ではあるが、総合性能の確定的な上位版ではない**。

次の優先事項は以下である。

1. 教師発話を出す前に、問題条件、式、数値、生徒回答を独立検算する。
2. frontier / one_step_beyondの失敗例を重点的に追加し、正答を誤答扱いする例をhard negativeとして学習する。
3. 同一方針の反復を検出し、別表現、具体例、より小さい部分問題へ支援を切り替える。
4. 情緒的支援と理解確認の改善を維持しながら、数学的正確性と誤り診断を品質ゲートまたはlossで優先する。
5. v3.1を含めた同一60問・完全Judge集合で、prompt形式、コーパス内容、学習方式の寄与を切り分ける。
6. LLM Judgeだけでなく、人手による層化監査で誤答追認と数学的誤りの見逃し率を確認する。
