## 結論

v4 SFT教師は、初回60件のうち21件（35.0%）が品質検査を通過した。失敗分を最大3回追加生成した結果、最終採用は35件（58.3%）まで増え、14件を新たに回収した。残る25件（41.7%）は4回目までに品質通過できなかった。

## 解釈上の制約

1. retry後35件は、初回採用21件と追加生成で回収した14件の混合集合であり、独立な35サンプルではない。
2. retry新規採用は品質検査を通過するまで再サンプリングされた条件付き出力で、初回生成性能と直接比較できない。
3. 最終不採用25件にはJudge得点がなく、最終34件の平均は全60問の平均を表さない。
4. `math_train_912`は生徒らしさ評価が欠けるため、複合指標とscope集計から除外した。
5. 数学Judgeの正答は最終解答の一致であり、導出、知識源、教師指導の妥当性を保証しない。
6. LLM Judgeによる評価であり、人手監査との一致率は未測定である。

## 改善優先順位

1. Phase 1・Phase 2の知識源をプロフィールの正規化済み知識IDと教師発話の厳密な引用へ拘束する。
2. 感情・confidence更新を決定的状態遷移で生成後に補正し、retryの主要失敗を減らす。
3. 教師発話前に数式と計算を独立検算し、生徒の正答を誤答扱いする逆方向の誤診断を防ぐ。
4. 完了判定を、生徒自身の説明・検算・類題適用が確認できた場合だけTrueにする。
5. retry上限は現状の追加3パスを維持し、それ以上増やす前に失敗理由別のプロンプト・正規化を改善する。
6. Judge完了判定を各必須フィールドの実在で検査し、`error`を持つ部分評価を`fully_evaluated`にしない。
7. 報告時は初回採用、retry新規採用、最終不採用を必ず分離し、上書き集計を避ける。
